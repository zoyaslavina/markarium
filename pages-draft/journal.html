Introducing {{PRODUCT_NAME}}

A private Markdown environment for reading a document as a whole, attaching feedback in context, and returning one coherent review.

By Zoya Slavina · approximately {{READING_TIME}} min read

Markdown is easy to produce and easy to move between tools. Reviewing it is less tidy. A document may arrive from a collaborator or an AI system, while the comments about it accumulate in a chat, task list or second file. The text changes, the feedback loses its location, and the reviewer has to reconstruct the relationship between them.

The original problem

I wanted a small tool that treated a Markdown document as the centre of the review. I could read the whole thing, select the exact passage that needed attention, attach a comment or task, edit the source and hand the result back without opening an account or uploading the file.

What the standalone edition became

The result is one self-contained HTML file. It renders GitHub Flavored Markdown and offline formulas, builds an outline, searches long documents and keeps multiple files in tabs. The same interface supports raw Markdown editing, contextual comments, checkbox tasks, highlights, clean export and annotation hand-off.

The distinctive part is the anchor. A note stores not only the selected quote, but also nearby text, its section and its block context. If the passage moves or changes slightly, the application has several signals it can use to reconnect the feedback.

Why one file matters

The parser, sanitizer, formula renderer, fonts and interface are embedded in the HTML. There is no package installation, build command, account, analytics service or CDN. The file can be opened directly from disk, inspected, archived and shared under the project licence.

Accessibility and agent navigation

The project uses semantic landmarks, tab and panel relationships, named controls, visible focus, live status messages and complete keyboard paths. These decisions are primarily about human access. They also make the interface more legible to software agents because important actions and relationships exist in the document structure instead of only as visual coordinates.

The boundary of the web edition

The strict portable security model blocks remote and relative document images. Direct file saving also varies by browser. Those are explicit boundaries, not hidden omissions. The desktop app will carry the same review workflow into native file handling, local images, Mermaid diagrams, expanded syntax and richer exports.
