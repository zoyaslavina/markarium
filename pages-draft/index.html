Why this exists

Review should not become another conversation to reconstruct.

I began this project while reviewing LLM-generated drafts and exchanging documents with collaborators. Commenting inside a chat turned each observation into another prompt. The document was in one place; the reasoning about it accumulated somewhere else.

I wanted to read the whole text, attach feedback where it belonged, turn parts of that feedback into tasks, and return one coherent review. That became a local-first Markdown environment where reading, comments, editing and hand-off remain part of the same object.

Current premise: the useful unit is not a comment floating beside a document. It is a comment with enough textual context to find its way home after the document changes.

Project principles

Small enough to understand. Capable enough to work in.

The standalone edition is intentionally package-free and self-contained. Its constraints are part of the product, not merely a deployment choice.

Local-first

No account, analytics, CDN or automatic network calls. Documents remain in browser storage or files the user explicitly handles.

Durable review

Comments, highlights and tasks use their quote, surrounding text, section and block context to survive small edits and movement.

Accessible structure

Keyboard paths, semantic regions, named controls, visible focus, high contrast and reduced motion are part of the HTML edition.

Agent-legible

The same stable identifiers and explicit relationships that help assistive technology also make the interface easier for software agents to inspect.
